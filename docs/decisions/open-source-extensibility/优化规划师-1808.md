# 开源可扩展性方案（优化规划师，2026-10-28 18:08）
目标：别人 clone 仓库后，改一份配置和几份角色文件就能跑起自己的「情报站」，不绑定 Grok Bot、Notion 或某个搜索服务。

## 1. 目录约定
```
station.yaml            # 集中配置
roles/<role>.md         # 角色模板（纯文本指令）
protocols/              # 公共条款：round、lock、证据文件、A/B 分类、例会
adapters/search/*.md    # 搜索后端说明 + 调用约定
adapters/storage/*.md   # 存储后端映射
schemas/                # manifest、plan、search、eval、retro 的字段定义（JSON Schema）
CHANGELOG.md
```

## 2. 新增或替换 bot 角色
- 角色模板固定 7 节：职责、输入文件、输出文件、触发方式（消息、定时、事件）、可用工具、禁止事项、交接对象。
- I/O 只通过文件，不依赖对话：输入是 rounds/<id>/*.md 和 decisions/<主题>/；输出写入约定路径；消息里只放「路径 + 摘要」。
- 替换角色时：只要满足同一份 I/O 约定即可，不必改动其他角色。在 station.yaml 的 roles 中启用、停用或改名。
- 最小可运行集合：协调者（BrainStorm）+ 搜索 + 评估 + 归档（Memory）；其余（配图、Todos、优化规划师）都是可选角色。

## 3. 搜索后端可插拔
- 统一接口：输入 query、时间范围、条数，输出 search 结果表（title、url、source、date、snippet、signals）。
- 在 station.yaml 的 search.chain 中按顺序列出后端，例如 [firecrawl, searxng, curl_cffi+markitdown, jina, crawl4ai]。按顺序降级，每次降级都写进 plan。
- 每个后端说明文件写明：前置检查（如 status 命令）、所需环境变量名（不写具体值）、限额、已知被拦的站点。
- 只作发现渠道的平台（小红书等）在配置中标为 discovery_only，不进入结果来源。

## 4. 存储可替换
- 唯一真源：仓库里的 manifest.json 加 Markdown 文件，由归档角色唯一写入。
- 镜像适配器：notion、obsidian、local-md、none。都是单向同步：按 manifest_id 做 upsert；content_hash 不变就跳过；删除的条目标 archived。
- Obsidian 和本地 Markdown 方案：每个条目一个 .md 文件，元数据放 front-matter，用 wikilink 关联 round 和 decision。
- 看板只读 manifest.json（GitHub Pages），与镜像方式无关。

## 5. 配置集中（station.yaml）
- 内容包括：时区、夜间窗口、例会时间、轮值规则、各档位阈值、超时、角色清单、搜索链、存储适配器、通知方式。
- 密钥只写环境变量名；提供 .env.example，并把 .env 加入 .gitignore。
- 加一个开轮前的校验脚本，检查配置字段、必需的环境变量是否存在、目录是否齐全。

## 6. 平台无关的纯文本指令
- 角色文件只写行为和文件约定，不写平台专属的工具名。平台差异放进 adapters/platform/<平台>.md（grok-bot、claude-code、cursor、自建 cron 等），说明消息、定时、优先级在各平台上如何实现。
- 「priority:true」等抽象成「需对方处理的通知」，由平台适配文件映射到具体实现。

## 7. 版本与变更记录
- 用语义化版本号：协议改动升主版本，加条款升次版本，措辞改动升补丁版本。每个角色文件头部写上 version 和 requires_protocol。
- CHANGELOG.md 每条写：日期、版本、改了什么、来源决策文件、影响的角色。
- 改指令一律走 B 类：先起草，再评审，再由用户确认，最后由 Memory 推送。打 tag 后，看板页脚显示当前协议版本。

## 8. 分步落地（建议）
P1（本周）：抽出 station.yaml、roles/ 和 CHANGELOG。P2：写 schemas 和校验脚本。P3：local-md 存储适配器，加上平台适配文件。以上每步推送仓库都属 B 类。
