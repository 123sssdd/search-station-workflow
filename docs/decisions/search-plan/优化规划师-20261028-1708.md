# 评审：每轮搜索执行方案模板 v0（优化规划师，2026-10-28 17:08）
针对：01-20261028-1705.md

## 结论
方向对（先定标准再搜、有门禁）。主要问题是：方案按「量」驱动、偏重，且第 0 步每轮都重做，成本高。建议改成「标准复用 + 量随任务分档 + 以信息饱和作为准出条件」。

## 意见
1. **第 0 步缓存复用**：把 standards 存入 standards/<领域>.md，有效期 30 天。同领域再搜时直接复用，只做 5 分钟增量检查；新领域或过期时才做全量预搜。这样可省掉大部分 15–30 分钟的预搜。
2. **数量分三档**，在方案里选定：
   - S（快速查询）：候选 ≥30，入选 3–5 条。
   - M（默认）：候选 60–100，精评 ≥20，入选 8–12 条。
   - L（专题）：保持 v0 的数值。
   固定 100–200 条容易逼出低质量的凑数。
3. **准出改为饱和判断**：在达到当档下限的前提下，若连续 2 组关键词的新增有效结果低于 10%，就可以结束。去掉「单轮不少于 45 分钟」这条下限：按时长考核会鼓励拖时间，改成时长上限（S 30 分钟、M 90 分钟、L 180 分钟）。
4. **关键词矩阵**：按档位定数量，S ≥8 组、M ≥20 组、L ≥30 组。命中为 0 的词组记录下来，不计入执行率分母，避免机械地凑满 90%。
5. **评论区**：只对入选结果抽读，且只抽前 10 条加最新 5 条。没有评论区的类型（论文、官方文档）免抽读。小红书、知乎、B站仍只作发现渠道，不登录、不批量抓取。
6. **评估分工**：第 1 轮初筛交给 Searcher 自动做；第 2 轮精评由质量评估负责；第 3 轮抽检比例改为 10%（至少 3 条）。分歧超过 1 分的条目只重评该条，不必整轮回到第 2 轮。
7. **进度汇报**：每 30 分钟一次过频且会唤醒其他 bot。改为只在阶段结束时写入 plan 文件，阻塞时才发 priority:true。
8. **文件合并**：standards 和 plan 合为同一个 plan-<id>.md 的两节，文件数从 4 个减到 3 个（plan / search / eval），与现有证据规则一致。

## 推荐
采纳 1、2、3（降本最多，同时保住质量），4–8 一并采纳。均为 A 类流程调整，写进指令时按 B 类走用户确认。
