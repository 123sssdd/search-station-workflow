# 2026-10-28 规则决定（主 bot 拍板，来源：优化规划师两轮方案/审查）

1. **交接凭证**：每轮须有 `rounds/search-<轮次id>.md`（Searcher）与 `rounds/eval-<轮次id>.md`（质量评估）；缺一只算「草案」，Memory 不推送 manifest。Memory 推送还须附用户确认原话（含时间）。
2. **priority 规则**：需对方行动（派任务/等结果/复核/归档）一律 priority:true；仅 FYI 用 false。
3. **轮值 + 锁**：轮次 id `<YYYYMMDD-HHMM>-<01|02>`（UTC+8）。单号日 01 开轮、双号日 02 开轮；一轮归锁 owner 到底（跨日不换）。不当值收到用户内容 → priority:true 转当值方并告知用户。锁 `rounds/<轮次id>.lock` 写 owner/开始时间/进度，逐步更新，结束改名 `.done`；6 小时无更新过期，接手方先告知原 owner。
4. **复核**：发排序给用户前，另一主 bot 检查两份证据与有无跳步，回「通过」或「不通过+原因」；30 分钟无回复则标注「未经复核」发出。
5. **主 bot 阅读边界**：只读用户亲自发来的那一个链接/文件；其余搜索抓取全交 Searcher。
6. **小红书/知乎/B站**：只作发现渠道，追溯 GitHub/博客/文档原始出处；需正文请用户转发；box 登录须用户明确同意且手动低频；禁止批量自动化与 MediaCrawler。
7. **搜索栈**：WebSearch 发现；读页 curl_cffi+MarkItDown → Jina r.jina.ai → Crawl4AI。
8. **Firecrawl**：待用户提供自己注册的免费 API key（不建议购买第三方 key）；Searcher 每轮检查 FIRECRAWL_API_KEY / `firecrawl` 登录状态，有则首选，无则本地栈并在 search 文件注明。
9. **规则决定归档**：存 Memory 记忆或本目录，不写 manifest，不需证据文件。
