# 给绘图工具组织输入

选择本次需要的一种模板。替换花括号内容，删掉不适用项；模板中的举例不能直接当成当前项目事实。用户指定工具时按该工具接受的输入方式提交，不把所有约束重复堆成超长提示词。

## 生成一张新图

```text
任务：为「{项目名}」生成一张{图型}，用于{项目介绍/技术文档/评审/社交图片}。
这张图只回答：{读者看完应理解的问题}。
内容性质：{当前实现/方案设计/示例}，范围：{起点、终点和边界}。

风格：浅色纸面、深藏蓝轻手绘描边、柔和粉彩分区、清楚的角色图标，规整容器与易读文字。标题紧凑，正文短而准确。若有附件，{附件名称}只作为{视觉参考/内容依据/编辑目标}，不要混淆角色。
标题：{准确标题}
语言与画幅：{语言；尺寸或比例；阅读场景}

结构：{本图应采用的规范结构，例如参与者与生命线、实体与基数、状态与触发事件}
节点/参与者/实体：{稳定编号、名称、职责或关键属性}
关系/消息/迁移：{逐条列出起点、终点、含义、方向、顺序或触发条件}
分支与边界：{返回、重试、并行、终止、外部服务及尚未实现部分}
图例：{只列本图使用的符号与线型含义}

不得新增或改写的事实：{需要锁定的组件、协议、消息方向、基数、指标等}
交付：{图片格式或可编辑源格式}；文字清楚，连线端点准确，遵守以上关系。
```

从图型规则中选 2–4 条最容易出错的要求补入提示词即可。例如时序图明确“参与者横坐标固定、每条消息锚定两条生命线、SSE 经接口返回”；ER 图明确“外键和基数依据模型，不把所有关系画成一对多”。

## 修改已有图

```text
编辑目标：{明确文件或已选中的图像版本}。
保留：{画幅、标题、参与者位置、正确连线、图标与配色等}。
仅修改：
1. {区域、现有错误、准确的替换内容或正确关系}
2. {必要的下一项；没有则删除}

所有新连线的起点与终点：{精确参与者/节点名称}。
不要移动不相关的节点，不新增组件或指标。输出{完整修正版/用户指定区域}。
```

输入“上一张”之前确认工具实际选中了哪个版本。若有多个候选，附上目标图或选择明确的资源，不能只依赖对话顺序。整图重新排版后必须重新检查已通过的关系。

## 同系列多张图

```text
为{项目}制作{数量与用途}图解。
统一风格：{参考图或视觉规范}。
每张图各自回答：
1. {图型}：{主要问题与内容边界}
2. {图型}：{主要问题与内容边界}
共享命名与颜色：{角色和技术名称映射}。
各图使用自己的图型结构；每张分别检查关系与文字，再作为一组交付。
```

## 建议给内容依据使用的简短格式

复杂项目在本地保留以下信息即可，不需要让每次简单画图都填完一张长表：

```text
目的 / 图型 / 范围 / 实现或方案
节点：ID、名称、职责、依据
关系：起点ID → 终点ID、含义、条件、依据
时序附加：次序、返回、循环/并行范围
未核实项：缺什么材料，图中如何处理
输出：画幅、格式、指定工具与参考图
```
