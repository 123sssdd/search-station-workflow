# 浅色手绘技术图解视觉规范

这是默认风格的文字规范，不依赖某张图片、特定项目或私有文件。用户附有参考图时，先查看；明确的新风格与用途要求优先。

## 视觉语言

- **纸面**：近白或很淡的米白，纸张质感仅作轻微点缀，不让纹理影响小字和连线。
- **笔触**：深藏蓝轮廓，轻手绘感；容器和关系依旧对齐。避免抖动过大、随意涂鸦或模糊笔画。
- **配色**：低饱和浅蓝、浅绿、淡黄、浅粉、浅紫填充，细描边；颜色帮助区分角色、阶段、系统边界或状态，同一含义在同组图片中保持一致。
- **图标**：电脑、接口、数据库、机器人、文件、搜索、盾牌、容器等使用一致的线条粗细和简洁彩色填充。图标必须对应角色，不能借图标暗示未采用的产品。
- **文字**：短中文标签，保留技术名称和协议的准确拼写。主标题可用手写粗字，正文保持清楚；少量荧光笔底纹强调重点。
- **装饰**：书本、纸飞机、便签等少量使用；标题区和空白角落适合装饰，消息端点和分支区域不适合。

## 构图与密度

标题通常占画面顶部约 5%–8%，主体优先；副标题只在帮助理解项目价值或图的范围时使用。不同图型布局不同：

- **架构**：左侧层名与编号，右侧组件卡片；真实外部服务放独立区域。必要时补充关键链路和少量机制小图。
- **时序**：顶部参与者卡片，垂直生命线贯穿，横向消息按时间排列；阶段背景色可以分区，但不能移动生命线。避免在生命线中插入改变坐标的说明表格。
- **流程/数据流**：一条明显主路径，短分支在邻近位置展开，分支条件靠近出口；上下游和回路使用不同空间。
- **ER/模块关系**：围绕核心实体或模块分组，避免为满足竖版而重复实体，或把关系数量挤成不可读小字。
- **状态/部署**：以状态迁移或真实部署边界组织空间，不能套用逻辑分层来暗示实际网络拓扑。

社交平台项目介绍默认可用 3:4 竖版。技术文档、宽时序图或多实体关系图优先按拓扑选取合适画幅；用户固定比例时拆图。先删重复修饰，再增加留白或拆分，最后才微调字号。不能删除协议、条件或返回含义来掩盖拥挤。

## 同组图片的一致性

统一标题位置、角色配色、图标样式、边框粗细和边界说明样式；每张图回答一个主要问题。节点名称跨图保持一致，必要缩写应有说明。同一角色在架构图与时序图中可以有不同排版，不能有不同职责。

## 线条与阅读

连线起点和终点应落在节点边缘、端口或参与者生命线上，不能悬空或穿过无关节点。每种线型的含义取决于图型，图例与实际一致。空间不足时移动说明、调整路线或拆图，避免靠颜色猜测连线关系。

在完整尺寸和实际阅读尺寸检查。小红书图要缩到手机宽度看角色、步骤与关键条件；投屏图要看远距离可读性。可读性不能仅由“高清”“2K”或输出像素数量证明。

用户未要求改变风格时，避免大面积深色、霓虹、厚重 3D、大片装饰渐变、巨大标题和密集小字。文字风格规范已经足够使用；没有参考图片时不要虚构附件或引用不存在的资源。
