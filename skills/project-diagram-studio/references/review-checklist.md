# 交付前检查

检查当前候选的实际文件，不检查旧版本来证明新版本通过。简单图按需选项，复杂图保留一份简短检查记录。

## 内容与关系

- 图型是否回答了用户的问题，范围是否清楚？实现、方案、示例有没有混用？
- 名称、职责、中间件用途与数据依据是否正确？是否混入参考项目的组件或结果？
- 每条关系的发送者、接收者、方向和含义是否一致？箭头是否连接正确节点，是否错误跨过必要的中间方？
- 条件从实际判断点出发吗？正常、失败、等待、重试、取消、超时是否只画了证据支持的行为？
- 是否把并行画成串行、逻辑层级画成物理部署、阶段状态保存画成最终结果保存？
- 图例是否与本图线型一致？不要用架构图的虚线含义解释时序返回或 ER 关系。
- 数字能否追溯到输入数据及测试条件？示例数字与实测结果是否清楚区分？

## 按图型补查

| 图型 | 重点 |
| --- | --- |
| 时序 | 固定生命线；请求与返回对象；异步与事件流；loop/alt/par范围；调用结束条件 |
| 流程 / 算法 | 起止；分支条件；循环出口；异常与重试从正确节点发出 |
| 数据流 | 数据来源、载荷、转换与存储；离线/在线；数据流和控制流的区别 |
| ER | 实体、主键、外键、关联基数、可空性；逻辑关系与物理约束区分 |
| 状态 | 初始/终态；触发事件与守卫；等待、失败及恢复迁移 |
| 部署 | 真实宿主/容器/网络边界；入口与协议；端口、实例数和高可用证据 |
| 模块 / 类 | 依赖方向；接口、组合、继承和调用区别；避免把文件夹嵌套当依赖 |
| AI | Agent职责；工具协议；检索/生成边界；训练/评测/在线接入真实关系 |
| 页面交互 | 页面与操作；状态、跳转、返回和错误路径；概念设计是否标明 |
| 数据图表 | 原始数据、单位、轴、比例、样本条件；没有数据不能宣称实测 |

## 视觉与文件

- 全尺寸查看一遍，再按目标阅读尺寸查看；文字、条件和节点是否仍可读？
- 标签是否压线、乱码、溢出或重复？连线是否穿过无关节点？激活条是否偏离生命线？
- 图标、颜色和标题是否属于同一套视觉语言？是否因装饰牺牲主体空间？
- 文件能否打开，导出尺寸是否准确？SVG是否包含真实可编辑对象，而非只有一张嵌入的位图？
- 重画后重新检查主关系，不能假设未要求修改的部分保持正确。

## 验证结论的表达

分别记录内容核对、目视检查和文件检查，不能互相替代。只输出源码时说明尚未渲染；没有运行系统时说明依据是静态材料；有未修正问题时指明位置。格式验证或图片生成成功都不等于技术内容通过。

同一问题连续两轮修订没有改善时停止重复同样请求。在用户工具约束允许时换用精确绘图工具，否则保留可审阅草稿和具体问题说明；不要为了完成标记而忽略错误。
